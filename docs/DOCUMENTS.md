# Documents Module

## Назначение модуля

Модуль документов реализует три типа документов: Индивидуальное задание, Отзыв о практике, Титульный лист. Каждый документ генерируется из .docx шаблона через docxtemplater.

## Архитектура

### Поток работы со студентом

1. **Индивидуальное задание (ИЗ)**
   - Студент заполняет 7 обязательных полей
   - Поле "назначено" автоматически подставляется из когорты
   - Кнопка "Сформировать" активна только при заполнении всех полей
   - Студент скачивает готовый .docx

2. **Отзыв о практике**
   - Студент видит только свои данные (ФИО, группа)
   - Админ заполняет 7 полей review_* в админ-панеле
   - После заполнения админом — студент может сформировать

3. **Титульный лист**
   - Требует загрузки отчёта студентом
   - Админ ознакомляется и ставит галочку "допущен"
   - После этого студент может сформировать титульный лист

### Автосохранение

**Реализация:**
- Debounce 1000ms (не спамим запросами при быстром вводе)
- Batch updates: группируем изменения, отправляем пачкой
- Optimistic update: сразу обновляем UI, откатываем при 4xx/5xx
- Триггер: onBlur + Ctrl+S (явное сохранение)

## Файлы

### `src/modules/documents/components/DocumentForm.tsx`
- Универсальная форма для всех 3 документов
- Debounce + batch для защиты от спама
- Автосохранение при потере фокуса

### `src/modules/documents/components/DocumentGenerator.tsx`
- Кнопка "Сформировать документ" активна только при Ready статусе
- Проверка обязательных полей перед генерацией

### `src/modules/documents/components/ReportUploader.tsx`
- Ограничение: 10MB max, только .docx
- Оригинальное имя файла сохраняется в DB
- Прогресс-бар при загрузке

### `src/modules/documents/utils/document-schemas.ts`
- Zod схемы валидации для каждого документа
- REQUIRED_FIELDS — список обязательных полей

## Специальность

**Автоподстановка:**
- `specialty` автоматически подставляется из `direction_code + direction_name`
- Если direction изменились, specialty обновляется автоматически
- Backend трансформирует при генерации документа

## Страницы

- `/app/(cabinet)/documents/page.tsx` — личный кабинет
- `/app/(admin)/documents/page.tsx` — админ панель

## Лучшие практики

- Данные документа хранятся один раз (reuse между документами)
- Валидация на фронте + на бекенде (защита от плохих данных)
- Автосохранение с debounce — UX не падает
- Состояния документа вынесены в отдельный компонент
