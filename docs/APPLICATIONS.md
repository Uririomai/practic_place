# Applications Module

## Назначение модуля

Модуль заявок реализует публичную анкету, тестовое задание и отображение статусов заявок. Анкета динамическая — поля берутся из SurveyField текущей когорты.

## Архитектура

### Публичная анкета (без авторизации)

Поток:
1. Пользователь заходит по ссылке когорты
2. GET `/api/survey/fields?cohortId=` получает вопросы
3. Форма рендерится динамически
4. POST `/api/applications` отправляет заявку
5. После отправки — тестовое задание

### Автоподстановка данных

При повторной заявке:
- API возвращает только заявки текущего пользователя
- Фильтруем по userId — не берём чужие данные
- Merge: только заполненные поля подставляются
- Пользователь видит предзаполненные значения — может скорректировать

### Тестовое задание

#### Состояния тестового задания:
```
SUBMITTED → IN_REVIEW → APPROVED | REJECTED
     ↑                                    ↓
     └────────────────────┬───────────────┘
                        ↓
                   EDIT_REQUEST
```

**Статусы и их значения:**
- `pending` — тест отправлен, ожидает проверки
- `approved` — тест одобрен, можно подавать заявку
- `rejected` — тест не прошёл, можно исправить и отправить снова
- `not_submitted` — тест не отправлен

#### UI для состояний:
- **Pending**: иконка часы ⏳, текст "Тест на проверке"
- **Approved**: иконка галочка ✓, зелёный цвет, "Тест одобрен"
- **Rejected**: иконка крест ✗, красный цвет, "Тест не прошёл" + кнопка "Отправить заново"

#### Stream:
1. После анкеты → редирект на `/test`
2. Если тест не опубликован → skeleton loader
3. При отправке → статус `pending`
4. Админ проверяет → статус `approved`/`rejected`
5. При отклонении → кнопка "Отправить заново" (редактирование)

### TestTaskView компонент

- Авто-растягивание textarea при 3+ строках
- Счётчик символов для ограничения
- Кнопка "Отправить на проверку"
- Индикатор статуса (pending/approved/rejected)
